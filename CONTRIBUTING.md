# Как участвовать в проекте

Спасибо, что смотрите. Проект небольшой, и помощь полезна в первую очередь там,
где у него честно написано «не проверено».

## С чего начать

1. Прочитайте раздел «Что не проверено» в [README](README.md) — там перечислены
   места, где поведение заявлено, но не измерено. Закрытие любого пункта с
   замерами — самый ценный вклад.
2. Посмотрите открытые issues: там же может быть уже расписано, что нужно.
3. Задать вопрос про устройство проще, чем сразу писать код.

## Что нужно локально

- Node.js 22.12 или новее.
- LM Studio с загруженной чат-моделью и запущенным локальным сервером.
- Собранный whisper.cpp и модель — путь к ним берётся из `config.json`,
  в репозиторий они не попадают.
- Qdrant, если хотите трогать RAG.

```bash
npm install
npm run doctor     # проверяет LM Studio, Qdrant и пути
npm run dev
```

`npm run doctor` стоит запускать первым: почти все непонятные ошибки при первом
старте на новой машине — это несовпавший порт, не та коллекция или не
собранный whisper.cpp, и `doctor` их показывает сразу.

## Перед pull request

```bash
npm run typecheck
npm test
npm run build
```

`typecheck` и `test` обязательны. `build` — если трогали main-процесс или
native-часть: ошибки сборки там не видны в vitest.

Тесты лежат рядом с кодом в `*.test.ts` и используют vitest. Там, где модуль
завязан на Electron, подменяйте `app` через `vi.mock('electron', ...)` —
иначе `config.ts` упадёт на `app.getPath('userData')`.

## Чего не стоит присылать

- **Свои `data/*.md`.** Это персональный материал, он в `.gitignore` не случайно.
- **Свои `.env`.** Образец переменных — в `.env.example`.
- Скриншоты и записи экрана с рабочими материалами. Для демо приложение
  специально умеет закрываться от захвата, см. «Скрытие при демонстрации
  экрана» в README.
- Крупные модели и корпуса: репозиторий должен оставаться лёгким для клона.

## Стиль

Комментарии, README и документация — на русском, и это осознанно: проект
делают русскоязычные пользователи, и английский текст в коде рядом с русским
комментарием только мешает. Идентификаторы в коде остаются английскими.
Комментарий объясняет ограничение, которое из кода не следует, а не пересказывает
строку под собой.

Отступы, кавычки и порядок импортов — по соседнему коду, отдельного форматтера
в проекте нет.

## Что нужно особой аккуратности

**Приватность.** Приложение отвечает по вашему рабочему материалу, поэтому
изменения, которые начинают уводить личные записи в общий retrieval или в
ответ, ломают основную идею проекта. Проверяйте такое на `RAG_PERSONAL_TOP_K=0`
и на обычном значении.

**Чувствительность к настройкам.** Скорость генерации на слабой видеокарте
падает не в разы, а на порядок — из-за вытеснения KV-кэша в оперативную память.
Подробности и таблица замеров в README, раздел «Длина контекста в LM Studio
решает всё». Не «оптимизируйте» это без замеров.

## Пул-реквесты

Один PR — одна тема. Описывайте, что изменилось и почему, и прикладывайте вывод
`npm test`, если меняли поведение. Если PR большой, разбейте его — так проще
обсуждать.
